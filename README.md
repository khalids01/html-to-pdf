# Portfolio resume PDF renderer

An internal Bun/Elysia service that renders the portfolio's existing resume pages with Playwright Chromium. It is deliberately not a public HTML-to-PDF API.

## Deployment configuration

Copy `.env.example` to `.env` and set:

```env
PDF_SERVICE_SECRET_KEY=the_same_private_key_used_by_the_portfolio
PORTFOLIO_RESUME_ORIGIN=http://portfolio:4000
```

`PORTFOLIO_RESUME_ORIGIN` must be the portfolio container's Docker-network address. The Compose service is internal-only (`traefik.enable=false`) and stores PDFs in the persistent `pdf-cache` volume.

Set these variables in the portfolio deployment too:

```env
PDF_SERVICE_URL=http://html-to-pdf:3000
PDF_SERVICE_SECRET_KEY=the_same_private_key_used_by_the_renderer
```

The portfolio browser route remains `/resume.pdf`; it proxies the generated bytes, so the shared key is never sent to a visitor.

## Internal API

All routes require the exact header:

```text
Authorization: Bearer <PDF_SERVICE_SECRET_KEY>
```

- `POST /internal/resume/pdf` with `{ "variant", "layout", "version" }`
- `POST /internal/resume/cache/invalidate` with optional `{ "variant" }`

Only canonical layouts are accepted. The service constructs the source URL from `PORTFOLIO_RESUME_ORIGIN`, so callers cannot use it to render arbitrary URLs.

Cache files are keyed by variant, layout, resume update version, and renderer version. A resume update also calls the invalidation endpoint; the versioned key prevents stale output even if that cleanup request is temporarily unavailable.

## Local development

```bash
bun install
cp .env.example .env
bun run dev
```

Outside Docker, set `CHROMIUM_EXECUTABLE_PATH` if Playwright Chromium is not installed. The Docker image installs Chromium during build.
